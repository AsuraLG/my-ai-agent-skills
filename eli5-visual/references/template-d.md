# 模板 D：技术文档形态（技术档）

给技术受众解释**代码或报错**——此场景卡片仪式是负担，改用密排文档版式。「自己看明白」的场景，信息密度优先。

## 版式规格

- 单栏密排、`h2/h3` 层级结构
- 零 emoji、无渐变大卡、无装饰性插图
- 开头可放一句话 TL;DR

## 必备元素（按需使用）

- **代码块**：等宽字体 + 深色底 + 简单语法着色——用 `<span>` + CSS class 给关键字/字符串/注释上色，不引 JS
- **行内标注**：指向具体行的 callout（"第 12 行这里没判空，就是根因"）
- **报错场景**：stack trace 高亮框——关键帧标红、无关帧压灰
- **修复方案**：修改前/修改后对比（双栏或 diff 配色：删红增绿）
- 允许对比表格与小型示意图（如调用链示意）

## 内容要求

- 先给结论（根因/这段代码在做什么），再展开细节
- 报错场景讲根因链，不是复述表面报错文字
