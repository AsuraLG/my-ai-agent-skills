图省事也可 npm i -g best-claude-hud（装预编译二进制），但那份无签名，敏感环境不建议。

接进 Claude Code 的 statusLine hook

在 ~/.claude/settings.json 里把 statusLine.command 指向编译出的二进制绝对路径（别用 npx @latest，那会每次访问 npm）。用 --setup 或它的 TUI 配置段。

三条纪律

① 永远不要跑 --patch（除非你确实想让它改写 Claude Code）；② 如果额度段不需要或走网关，在配置里关掉 usage 段；③ 知道它会读钥匙串 OAuth——这是查额度所必需，接受则用。

路线 C · 换成 ccstatusline（想要最深的分段定制 / powerline） 
# 全局装好，避免 npx @latest 每次访问 npm registry
npm i -g ccstatusline
# 然后跑它的交互式配置器挑 widget / 主题
ccstatusline            # TUI 配置，写进 ~/.claude/settings.json

代价是 Node 冷启动延迟。换来的是：完全不联网、不读钥匙串、不带任何补丁器、社区最大最稳。 如果你对 best-claude-hud 那些"长手"不放心，这条是最干净的。

路线 D · 继续用 CCometixLine（什么都不做）

完全合理的选择——它没坏、隐私干净、最快。唯一要自己盯的： 用到新模型时看一眼成本段是否显示 $0 或明显算错（价表停在 2026-03，可能跟不上新模型定价）。 一旦发现算错，或想要新特性，再按路线 A 平滑迁移到它的 fork。

三条通用注意
  • 别用 npx/bunx …@latest 作 statusline 命令——每次渲染都会访问 npm registry（延迟 + 出网）。一律"全局装好 + 绝对路径引用"，气隙环境尤其。
  • 额度段会连官方 api.anthropic.com。若你的 Claude 走内部网关而非直连，关掉该段或设 api_base_url。
  • 没有一个支持 Codex（ccusage 的多 agent 用量命令除外，但那不是 statusline）。Codex 端继续用原生，或把 ccusage 当独立用量工具叠用。

风险与附录

赛道风险
  • 深度绑定 Claude Code，Codex 覆盖为零。所有工具都建在 Claude Code 的 statusLine hook + 读 ~/.claude 之上。换到别的 agent 生态就得重来。
  • 擂主→fork 的换血本身是信号。CCometixLine（3.4k★）停摆、其 fork best-claude-hud 一个月起量接棒——说明这类单人项目寿命不稳，押注要接受"可能再换一次"。
  • 好在切换成本极低：都只是 settings.json 里一行 command，换工具几秒钟的事、不碰你的代码。所以大胆试、别过度纠结。
方法与已知空白（诚实标注）
  • 直连 GitHub 被本次执行环境阻断（api.github.com/github.com TCP 不通）。star/日期改用 ungh.cc 镜像（二手），但关键的"CCometixLine 停更"用 npm 发布时间 + 仓库 CHANGELOG 一手三重交叉验证过；源码/依赖/LICENSE 均经 raw.githubusercontent.com 与 npm registry 取到一手原文。
  • v2 更新：ccstatusline 与 CCometixLine 的深挖已补齐——ccstatusline 经全 118 个源文件 grep 确认遥测，并据此把原"完全不联网"修正为"默认零联网（读 CC 原生字段），付费溢出 widget 才连第一方 api"；CCometixLine 停更的具体故障（#118/#121/#131/#111）也已坐实，不再是推测。
  • v3 更新 · 一次真实的漏检：初版横扫漏掉了全赛道采用度最高的 jarrodwatts/claude-hud（26.8k★）——由用户点名才补上。原因可能是 GitHub 直连被阻断、且 npm 上同名的是个过时 bash 包，掩盖了真实项目。教训：横扫不能只信一个检索入口；采用度最高的工具反而最容易因"名字太通用/被同名旧包盖住"而漏。补查后它成为主推。
  • 各工具的 issue 响应速度、GaoSSR 的其它履历因 api 阻断未查到。
  • 渲染延迟为"原生 vs Node 冷启动"的定性判断，未做同机毫秒级实测。best-claude-hud 是否修掉了 CCometixLine 那类"model 字段 schema 变化即崩"的脆弱性（它继承同架构、靠日更打补丁），未逐一核实。

本报告为选型辅助，不构成安全审计。涉及内网敏感环境时，"读钥匙串 token / 预编译二进制来源 / 额度段出网"这三点， 建议以你所在组织的合规要求为准——最稳妥是源码自编 + 关掉不需要的出网段。
