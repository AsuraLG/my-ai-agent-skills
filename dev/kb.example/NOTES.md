# kb.example 开发记录

> 本文件建立于 2026-08-10。

## 设计决策

### 定位是可复制模板，不是可直接用的 skill（3c145fc，2026-07-25）

这个目录与其他 skill 性质不同：它不能直接投入使用，需要复制到自己的 skill 目录后，把全文的 `{...}` 占位符替换成自己业务的信息。占位符含义写在 SKILL.md 文末的说明表里。

由此产生一个约束：**`name` 字段是 `kb` 而不是目录名 `kb.example`**，因为使用者复制后会改名，模板里写死目录名反而误导。这是本仓库唯一一个 frontmatter `name` 与目录名不一致的 skill。

### 真实业务信息全部替换为占位符（3c145fc，2026-07-25）

原始版本包含具体业务的知识库路径、业务关键词与服务名。发布到公开仓库前逐一替换为 `{目标业务}`、`{知识库项目名}`、`{业务关键词N}` 等占位符。

改动这个 skill 时要守住这条：不要把某次具体使用时填入的真实业务信息回写进模板。

### 三种协作模式按问题类型划分，不按工具可用性划分

`defaultMode` 三选一，判据是问题需要什么，不是哪个工具在线：

| 模式 | 适用问题 |
| --- | --- |
| `kb-only` | 业务背景、术语、领域边界、服务/SDK 导航、人工确认过的运行时事实 |
| `codegraph-only` | 不需要业务背景的纯代码问题；用户明确要看实现、符号关系、调用者/影响面 |
| `hybrid`（默认） | 既需要业务理解又需要实现细节——多数实际问题 |

工具可用性是另一个正交开关：`codegraphEnabled: false` 时强制走 kb-only。两者不要混为一谈。

### CodeGraph 索引维护默认不授权

`allowCodegraphIndexMaintenance` 默认 `false`：即使 `.codegraph` 缺失或过期，也不自行运行 CodeGraph 的写入/维护命令，而是把确切命令报给用户由其自行执行。索引是否重建是用户的决定。
