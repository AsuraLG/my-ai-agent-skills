## 设计决策

### 定位为「原始抓取」而非「摘要」

这是最先确立、也最需要守住的边界。默认输出偏向原始结果（标题、链接、必要元信息），摘要只在用户明确要求时才做。

原因是摘要会丢信息且不可逆——用户拿到摘要后无法还原原文，而拿到原文随时可以摘要。

### 有意保持简单：只抓第一页、只留一个参数

只抓搜狗微信搜索第一页、只保留 `--limit`（默认 10、上限 10），不做分页、不加排序过滤。

这不是「还没做」，是刻意的范围控制。扩大抓取范围会同时放大反爬风险和维护面。

### 代理从硬编码改为环境变量可选

最初抓取流程受硬编码代理配置影响，后改为默认不走代理、通过 `WECHAT_ARTICLE_FETCH_PROXY` 启用。这是明确确认过的产品约定，不要回退。

### fail-soft 而非单点失败中断

单篇文章失败不拖垮整个搜索结果，`content` 允许为空字符串。取舍是「整体可用性」优先于「单篇完美」。

## 踩坑记录

### 正文去噪先堆规则会误伤正文

已验证有效的顺序是：真实样本抽最小失败片段 → 补回归测试 → 再扩展 `NOISE_PATTERNS` → 确认旧行为未破坏。反过来做容易误伤正常正文。

具体操作约束已写进 `.claude/rules/wechat-article-fetch.md`。

## 当前状态

### 已完成

- **抓取主链路**：请求搜狗微信搜索页 → 提取候选跳转链接 → 解析真实 `mp.weixin.qq.com` URL → 请求文章 HTML → 提取标题/元信息/正文 → 输出 JSON
- **元信息提取**：标题、公众号名称、发布时间、作者。时间戳格式化为北京时间，可读文本原样保留
- **正文纯文本提取**：定位 `id="js_content"`，去 `script`/`style`，`<br>` 转换行，块级标签结束位置转换行，去其余 HTML 标签，归一化空白
- **正文噪音清洗**：已覆盖阅读原文、扫码/长按关注、独立观点声明、异议投诉声明、往期/相关/延伸推荐、出品丨作者丨编辑丨微信统筹丨、`End` 等典型尾部噪音
- **可选代理改造**
- **回归测试**（`tests/test_fetch.py`，unittest）：搜索页链接提取、正文段落换行保留、噪音过滤、`<br>` 换行、发布时间格式化、元信息提取、默认无代理、环境变量代理生效、`limit` 上限与非法值处理

### 已知问题（非阻塞，当前暂停）

1. **部分文章仍有残余尾部噪音**：文件下载提示、知识岛/社群/扫码加入类文案、投稿/商务合作类文案、图片来源/侵删声明、关注卡片与资料领取引导。这轮清洗工作主动暂停，不是阻塞点。
2. **少量文章正文为空**：标题和链接抓到了但 `content == ""`。设计上允许，属 fail-soft 行为。

### 推荐的后续迭代顺序

1. 基于真实样本继续补正文尾部噪音清洗规则
2. 补失败场景测试（文章抓取失败、跳转解析失败）
3. 在不破坏简单性的前提下提升正文提取稳定性
4. 最后才考虑新增能力
