# handoff 开发记录

> 2026-08-10 从 `skill_handoff_dev` 独立开发目录迁入本仓库。本文件由原 `README.md` 改写而成，
> 原 `docs/` 五份文档原样保留在同级子目录下。

## 这是什么

一个跨会话、跨 Agent、跨平台的工作交接能力。把「开新会话前让 AI 整理现状、该落盘的落盘、再产出一份可复制的 prompt」这套做法，从手工实践提炼成 skill。

要解决的问题（使用者原话）：

> 避免后续上下文压缩或者开新会话后讨论结果丢失导致实现偏差或者返工

被调用时跑五个阶段，产出两件东西，缺一不可：**该落盘的落盘**（本次会话的结论写进项目既有的长期文档）+ **一份能直接粘贴的 prompt**（只装指针，不装内容）。

**骨架是从真实产物归纳的，不是设计出来的**——spec §7 的十段结构来自 11 份真实历史交接 prompt（某项目三周内十余次人工会话交接）。

三个非显然的设计均来自使用者既有实践，不是原创：只装指针不装内容、自愈判定（内嵌可执行命令让接手方自验前提）、显式失效声明（「以顶部为准，下方全部过时」）。

## 判据顺序

改这个 skill 时按此顺序取判据，**spec 与实现冲突时以 spec 为准；spec 本身有疑问找用户裁决，不自行解释**：

1. `specs/2026-08-04-handoff-skill-design.md` —— spec 是判据
2. `decisions/2026-08-04-brainstorm-裁决台账.md` —— 哪些已定案、哪些是可推翻的推断
3. `research/2026-08-04-historical-handoff-corpus.md` —— 验证基准（本副本中仅存说明，见下）
4. `plans/2026-08-04-handoff-skill-implementation.md` —— 实现计划
5. `verification/` —— spec §10 三项验证的判据、执行记录与判定

## 设计决策

全部裁决及其出处见 `decisions/2026-08-04-brainstorm-裁决台账.md`。标「已定案」的不要重新提案；标「我的推断」的可以推翻，但推翻前先看理由。

几条改动时最容易踩到的：

- **D4 翻译对称性**：两边都精准，不设「母语平台」。其他平台的机制不得凭印象编写。
- **D6 接力与委派**：一个 skill 两种模式，不拆成两个。用户提出质疑，论证后确认。
- **I2 回填必须早于采集**：顺序反了，prompt 里的 HEAD 就是旧值，接手方自愈判定会对不上。
- **I3 上下文告急时优先交付 prompt**：被牺牲的是完整性不是准确性。标明「还有 N 条没落盘」的 prompt 可用，HEAD 写错的不可用。
- **D14 未定项清单可以写，但禁止给建议值**：标出空缺 ≠ 填充方法论。必须标注「这是需要裁决的空缺，不是既有需求」。

## 踩坑记录

### 把 Claude Code 当「母语」、别的平台当「降级」

设计初期的翻译是不对称的：Claude Code 侧写精准的 skill 名与工具名，Codex 侧降级成模糊的能力描述。

用户指出：「这个 skill 我也有可能在 codex cli 上去用哇」——那时 Claude Code 反而成了「外语」。

修正为两侧都走「探测 + 分级标注 + 用户校对 + 锁定」。并明确约束：其他平台的机制不得凭印象编写，那属于使用者 AI 协作规范里「转抄自别处、未核」一档。

### 回归验证的隔离手段偏离了 spec 字面

D13 裁定用 `git clone --local --no-hardlinks` 到临时目录，而 spec §10.1 写的是 worktree。

这是**有意偏离**：spec 的目的（D9「主工作区零风险」）由 clone 更彻底地达成——`worktree add` 会往源仓库 `.git/worktrees/` 写元数据，clone 对源仓库纯读。

连带隐患：`clone --local` 会把 `origin` 指回源仓库，必须摘除远端防误 push。

### 验证不能由跑过设计的会话自己做

D11 裁定由全新 subagent 执行 spec §10 三项验证。理由：主会话已完整读过 11 份历史交接 prompt，自己跑回归验证会无意识照着黄金答案写，判别力被污染。

## 当前状态

### 脱敏造成的能力缺失

这份是从私有开发仓库脱敏后的公开副本。以下内容已移除，因为它们整体由内部项目信息构成，无法逐句脱敏而不失真：

| 移除的内容 | 原本是什么 | 影响 |
| --- | --- | --- |
| 历史交接语料原文（11 份） | spec §10.1 回归验证的黄金基准 | **回归验证无法原样重跑**，重建方法见 `research/` 那份说明 |
| 三份回归验证的产物原件 | 被判定的 prompt 全文，用于复核判定 | 验证结论与方法保留在 `verification/`，但判定的原始依据无法复核 |
| 该仓库自己的 `.handoff/` 交接件 | skill 首次真实使用的产物 | 仅是示例，不影响使用 |

绝对路径、仓库名、commit、内部系统名一律替换为占位符（形如 `<本仓库绝对路径>`、`<历史项目>`、`<R1-commit>`）。要继续迭代，把占位符换成实际值即可。

`handoff/` 下的 skill 本体**从一开始就不含任何具体项目的信息**——那是设计约束（spec §3.3：项目形态一律靠探测得出），不是脱敏的结果。
