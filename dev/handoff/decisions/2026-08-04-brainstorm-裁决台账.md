## 二、我的推断（不在用户需求里，可推翻）

以下是我加的设计，用户未逐条明确要求。推翻前请看理由：

| # | 推断 | 理由 | 用户是否已确认 |
|---|---|---|---|
| I1 | 事实一律实测，不许凭记忆 | HEAD/测试数字/工作区状态是记忆最易错、错了代价最高的几样 | 未逐条确认，但未反对 |
| I2 | 回填必须早于采集 | 回填会产生提交，顺序反了 prompt 里的 HEAD 就是旧值，接手方自愈判定会对不上 | ✅ 明确认可（「1这个没问题」） |
| I3 | 上下文告急时优先交付 prompt，牺牲回填完整性 | 被牺牲的是完整性不是准确性；标明「还有 N 条没落盘」的 prompt 可用，HEAD 写错的不可用 | ✅ 明确认可 |
| I4 | ④ 类（用户裁定）条目锁定，探测不得自动覆盖 | 否则用户纠正过的条目会被推断值改回，同一错误需反复纠正 | 未逐条确认，但未反对 |
| I5 | 分级标注四档（① 实测 ② 推断 ③ 抄规范 ④ 用户说的） | 前三档直接来自使用者的 AI 协作规范文档第 1 节；④ 为本设计新增 | 未逐条确认，但未反对 |
| I6 | 五条 YAGNI（见 spec §12） | 每条都附了「何时重开」判据 | 已解释，用户未反对 |

## 三、我在设计中犯过的偏见（记录以免重犯）

**把 Claude Code 当"母语"、Codex 当"降级"。** 我最初设计的翻译是不对称的：
Claude Code 侧写精准的 skill 名与工具名，Codex 侧降级成模糊的能力描述。

用户指出：「这个 skill 我也有可能在 codex cli 上去用哇」——那时 Claude Code 反而成了"外语"。

**修正**：两侧都走「探测 + 分级标注 + 用户校对 + 锁定」，对称精准。
且明确约束：**其他平台的机制不得凭印象编写**，那正属于用户规范里「转抄自别处、未核」一档。

## 四、设计的证据基础

spec §7 的十段骨架不是发明的，是从 11 份真实历史 prompt 归纳的。
语料见 `docs/research/2026-08-04-historical-handoff-corpus.md`。

三个非显然的设计均来自用户既有实践，不是我的原创：

- **只装指针不装内容**——「先读事实源，别凭上下文推断」
- **自愈判定**——内嵌可执行命令让接手方自验前提
- **显式失效声明**——「以顶部为准，下方全部过时」
