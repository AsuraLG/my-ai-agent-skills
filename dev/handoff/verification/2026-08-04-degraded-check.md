### 一处待你复核的边界判断（subagent 代批，我认为合理但不替你定案）

subagent 在 prompt 第 7 段加了一个「未定项」子块（语言/技术栈、目录结构、是否引入测试框架、
提交信息风格），并显式标注「这些是需要用户裁决的空缺，不是既有需求」。

它的理由：**标出空缺 ≠ 填充方法论**；不写的话，接手方接到「加第一个模块」会自行选语言建目录，
那才是真的替用户做了决定。

我的判断：不违反 spec §5.6（没有给出任何具体建议值，只列出「这几件事没定」）。
但这是 skill 输出里唯一一处「探测不到时仍然写了点什么」的地方，边界由你定。

### 本次额外查出的一个缺陷（已修复）

subagent 在增量校验第 2 项发现输出为空，**主动起疑并复核**，查出 `detection.md` 的命令有缺陷。
我独立实测复核（不采信它的说法，自己跑）：

```
$ date                                              → 2026-08-04 18:33
$ git log --since="2026-08-04"        --oneline | wc -l   → 0      ← 漏掉全部 7 个提交
$ git log --since="2026-08-04 00:00"  --oneline | wc -l   → 7
$ git log --oneline | wc -l                               → 7
```

⇒ 断言成立：git 的 approxidate 把裸日期解析为「该日期的**当前时钟时间**」而非当日零点。
**profile 生成当天再跑 handoff，增量校验第 2 项会永远返回空**，而空输出与「确实没有新增」
无法区分——是一个没有任何迹象的静默漏报。

修复：`detection.md` §四.2 的命令改为 `--since="<生成日> 00:00"`，并把这个坑连同实测证据写在旁边。
