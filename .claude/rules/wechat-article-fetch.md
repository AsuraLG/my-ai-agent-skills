# wechat-article-fetch 开发约束

改这个 skill 的代码时必须遵守。决策背景与已知问题见 `dev/wechat-article-fetch/NOTES.md`。

## 产品定位（首先守住这条）

这是一个**原始信息抓取** skill，不是摘要 skill。

- 用户没特殊说明时：默认返回抓到的文章标题 + 原始微信链接
- 用户明确要求「摘要 / 总结 / 提炼」时：才基于 `content` 做摘要
- 用户明确要求「正文」时：才展开正文文本

不要把默认行为改成「自动摘要优先」。

也不做通用网页搜索，不做公众号后台管理。

## 抓取范围

- 只抓搜狗微信搜索**第一页**，不做分页。不要重新引入分页逻辑，除非需求明确变化。
- 只保留一个业务参数 `--limit`：默认 10，上限 10，超过截断到 10，小于等于 0 抛错。
- 不要主动引入更多搜索参数、排序或过滤逻辑。当前的简单是有意为之。

## 输出结构

脚本返回 JSON，字段：`title`、`url`、`account_name`、`publish_time`、`author`、`content`。

`content` 是提取后的正文纯文本，不是 HTML。

`publish_time`：抓到 Unix 时间戳则格式化为北京时间 `YYYY-MM-DD HH:MM:SS`；抓到可读文本则原样保留。

## 代理

默认关闭。仅当环境变量 `WECHAT_ARTICLE_FETCH_PROXY` 存在时才同时配置 HTTP/HTTPS 代理。不要恢复硬编码代理。

## 失败处理：fail-soft，不要单点失败中断全部结果

- 搜索结果页没解析出可用文章：返回空结果，不编造内容
- 某篇文章跳转解析失败：跳过该条，继续处理其他结果
- 某篇文章正文抓取失败：仍返回标题/链接等基础结果，`content` 允许为空字符串

不要为了追求单篇完美而降低整体可用性。

## 正文去噪必须测试驱动

扩充去噪规则时按这个顺序，不要反过来：

1. 从真实抓取样本抽出最小失败片段
2. 在 `tests/test_fetch.py` 补回归测试
3. 再扩展 `NOISE_PATTERNS` 或清洗逻辑
4. 确认旧行为未被破坏

先堆规则再补测试容易误伤正常正文。

## 改动要求

改了参数、默认返回策略、代理行为、输出 JSON 结构或失败处理方式，必须同步更新 `SKILL.md`。
